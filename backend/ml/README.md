# SmartGridFaultAI — Machine Learning Pipeline (Step 3)

## 1. Overview

This module implements **Step 3** of the **SmartGridFaultAI** platform: a reproducible machine learning pipeline for **fault classification** and **fault localization** built directly on top of the Stage 2 physical electrical simulation engine.

All training and evaluation data are derived from physically meaningful 3-phase transient simulations (solving differential equations for RLC transmission lines with realistic load, line impedance, and fault parameters) rather than synthetic or fabricated numbers.

> **CRITICAL DISCLAIMER (Simulation vs. Real-World Performance):**  
> This baseline ML system is trained and evaluated strictly on **simulated electrical grid data** generated by the system's physical simulation engine. **Performance on simulated data does not establish or guarantee performance on real-world utility grid measurements.** Real power grids exhibit non-ideal noise, sensor saturation, CT/VT harmonic distortion, high-impedance arcing dynamics, and network topology changes not fully modeled here.

## 3. Physical Feature Extraction (26 Features)

The feature extraction module (`backend/ml/feature_extractor.py`) computes 26 physically meaningful electrical features from sending-terminal measurements without target leakage.

| Feature Name | Category | Physical Description |
|:---|:---|:---|
| `va_rms`, `vb_rms`, `vc_rms` | Phase Voltages | Per-phase RMS voltage (kV) |
| `v_avg_rms` | Voltage Average | Mean of phase RMS voltages (kV) |
| `voltage_deviation` | Voltage Variation | Relative max deviation from mean voltage |
| `voltage_imbalance` | Voltage Symmetry | Voltage unbalance factor $(V_{max} - V_{min}) / V_{avg}$ |
| `ia_rms`, `ib_rms`, `ic_rms` | Phase Currents | Per-phase RMS current (A) |
| `i_avg_rms` | Current Average | Mean of phase RMS currents (A) |
| `current_deviation` | Current Variation | Relative max deviation from mean current |
| `current_imbalance` | Current Symmetry | Current unbalance factor $(I_{max} - I_{min}) / I_{avg}$ |
| `v1_mag` | Symmetrical Components | Positive-sequence voltage magnitude (kV) |
| `v2_mag` | Symmetrical Components | Negative-sequence voltage magnitude (kV) |
| `v0_mag` | Symmetrical Components | Zero-sequence voltage magnitude (kV) |
| `i1_mag` | Symmetrical Components | Positive-sequence current magnitude (A) |
| `i2_mag` | Symmetrical Components | Negative-sequence current magnitude (A) |
| `i0_mag` | Symmetrical Components | Zero-sequence current magnitude (A) |
| `v2_v1_ratio` | Sequence Ratio | Negative-to-positive sequence voltage ratio ($V_2/V_1$) |
| `v0_v1_ratio` | Sequence Ratio | Zero-to-positive sequence voltage ratio ($V_0/V_1$) |
| `i2_i1_ratio` | Sequence Ratio | Negative-to-positive sequence current ratio ($I_2/I_1$) |
| `i0_i1_ratio` | Sequence Ratio | Zero-to-positive sequence current ratio ($I_0/I_1$) |
| `phase_imbalance` | Asymmetry Indicator | Combined phase asymmetry index |
| `apparent_impedance_mag` | Line Impedance | Total apparent loop impedance $Z = V_{phase}/I_{phase}$ ($\Omega$) |
| `apparent_reactance_x1` | Reactance Estimation | Apparent positive sequence reactance component ($\Omega$) |
| `line_length_km` | Line Topology | Total transmission line length (km) |

### Strict Anti-Leakage Verification
The following labels and metadata are **explicitly excluded** from the feature matrix $X$:
- `fault_type` (classification target)
- `affected_phases` (classification metadata)
- `fault_distance_km` (localization regression target — **never included in $X$**)
- `sample_id`, `actual_rf_ohm` (administrative metadata)

## 4. Dataset Generation

The dataset generator (`backend/ml/dataset_generator.py`) generates balanced, reproducible simulation samples by executing the physical electrical engine (`SimulationEngine.run_simulation`) across randomized operating states with fixed seed `random_seed=42`.

### Varied Electrical Parameters:
- **Base Voltage**: 110 kV, 132 kV, 220 kV, 400 kV
- **Frequency**: 49.5 Hz – 50.5 Hz
- **Load Active Power**: 10 MW – 100 MW
- **Power Factor**: 0.82 – 0.95 lagging
- **Line Length**: 20 km – 100 km
- **Fault Types**: 7 classes (`NORMAL`, `LG`, `LL`, `LLG`, `LLL`, `OPEN_CIRCUIT`, `SHORT_CIRCUIT`)
- **Fault Distance**: 10% – 90% of total line length
- **Fault Resistance**: 0.05 $\Omega$ – 25.0 $\Omega$
- **Fault Timing**: Start time 0.04 s – 0.08 s, duration 0.04 s – 0.10 s

### Class Distribution (420 Total Samples):
| Class Name | Sample Count | Percentage | Electrical Characteristics |
|:---|:---:|:---:|:---|
| `NORMAL` | 60 | 14.29% | Balanced voltages, $I_2 \approx 0, I_0 \approx 0$, low current |
| `LG` | 60 | 14.29% | Single line dip, high ground current, $I_0 > 0, I_2 > 0$ |
| `LL` | 60 | 14.29% | High phase-to-phase current, $I_2 > 0, I_0 \approx 0$ |
| `LLG` | 60 | 14.29% | Two phase dip, earth return, $I_2 > 0, I_0 > 0$ |
| `LLL` | 60 | 14.29% | Severe symmetrical current spike, $I_1 \gg 0, I_2 \approx 0, I_0 \approx 0$ |
| `OPEN_CIRCUIT` | 60 | 14.29% | Disconnection on phase, zero phase current, moderate unbalance |
| `SHORT_CIRCUIT` | 60 | 14.29% | General 3-phase shunt fault to earth with zero sequence path |

## 5. Model Architecture & Hyperparameters

### 5.1 Fault Classifier
- **Algorithm**: `RandomForestClassifier` (Scikit-Learn)
- **Hyperparameters**: `n_estimators=100`, `max_depth=12`, `random_state=42`, `class_weight='balanced'`
- **Validation Scheme**: Stratified 80/20 train/test split (336 train samples, 84 test samples; exactly 12 test samples per class)
- **Top Predictive Features**:
  1. `i0_i1_ratio` (10.53% importance)
  2. `v0_v1_ratio` (9.96% importance)
  3. `current_imbalance` (9.50% importance)
  4. `phase_imbalance` (9.28% importance)
  5. `i2_i1_ratio` (8.65% importance)

### 5.2 Fault Localizer
- **Algorithm**: `RandomForestRegressor` (Scikit-Learn)
- **Hyperparameters**: `n_estimators=100`, `max_depth=12`, `random_state=42`
- **Validation Scheme**: 80/20 train/test split on faulted samples (288 train samples, 72 test samples; `NORMAL` samples excluded)
- **Target**: `fault_distance_km` strictly derived from line impedance, reactance, and symmetrical voltage/current magnitudes.

## 7. Dual Engine & API Architecture

The ML models operate alongside the Stage 2 deterministic baseline without replacing it:

```text
Simulation Engine Output
         │
         ├──► Rule-Based Baseline Engine (Stage 2)
         │    ├── Fault Detection (overcurrent / voltage dip thresholds)
         │    ├── Fault Classification (Fortescue sequence thresholds)
         │    └── Fault Localization (Takagi / Reactance algorithm)
         │
         └──► ML Inference Service (Stage 3)
              ├── Feature Extractor (26 features)
              ├── RandomForestClassifier ──► MLPrediction (predicted type + probabilities)
              └── RandomForestRegressor  ──► MLLocalization (estimated km + distance %)
```

### Response Schema Extension (`/api/simulation/run`):
The existing Stage 1/2 response schema remains completely backwards-compatible. Two optional ML sections are appended:

```json
{
  "simulation_id": "sim_20261002_001",
  "fault_detected": true,
  "fault_type": "LG",
  "affected_phases": ["A"],
  "estimated_fault_distance_km": 30.0,
  "breaker_status": "TRIPPED",
  "ml_prediction": {
    "enabled": true,
    "fault_type": "LG",
    "confidence": 0.96,
    "model_name": "RandomForestClassifier",
    "class_probabilities": {
      "NORMAL": 0.0,
      "LG": 0.96,
      "LL": 0.0,
      "LLG": 0.04,
      "LLL": 0.0,
      "OPEN_CIRCUIT": 0.0,
      "SHORT_CIRCUIT": 0.0
    }
  },
  "ml_localization": {
    "enabled": true,
    "estimated_fault_distance_km": 28.64,
    "estimated_distance_percent": 57.28,
    "model_name": "RandomForestRegressor"
  }
}
```

If the model files are missing or uninitialized, the API responds gracefully with `"enabled": false` and `"fault_type": "UNAVAILABLE"`, without breaking the simulation.

## 8. CLI Commands to Reproduce Pipeline

Run all commands from the `backend/` directory:

### Run Full Pipeline (Generate, Train, Evaluate, and Test Inference):
```powershell
python -m ml.run_pipeline
```

### Run Modular Commands Individually:
1. **Generate Dataset**:
   ```powershell
   python -m ml.dataset_generator
   ```
2. **Train Classification Model**:
   ```powershell
   python -m ml.train_classifier
   ```
3. **Train Localization Model**:
   ```powershell
   python -m ml.train_localizer
   ```
4. **Evaluate Saved Models**:
   ```powershell
   python -m ml.evaluate_models
   ```
5. **Run Automated Test Suite (Unit & Integration)**:
   ```powershell
   pytest tests/test_ml_pipeline.py -v
   ```
   Or run the complete test suite:
   ```powershell
   pytest tests/ -v
   ```
